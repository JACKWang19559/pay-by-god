# BOSS 直聘附件简历投递

## 定位 CLI 和职位

从当前工作目录及其父目录，或用户提供的项目路径寻找 `package.json` 的 `name` 为 `boss-cli` 且包含 `bin/boss.js` 的项目根目录。技能可能被复制安装到其他位置，不依赖技能目录推算项目路径，不写死本机路径；找不到时才询问位置。

以下命令均在项目根目录运行。先用本地 `node bin/boss.js --help` 确认支持的参数，复用用户选定的 profile / CDP 会话；预览和提交必须使用同一账号。环境或登录未就绪时，按项目 README 的安装及 `login` 流程处理。

用最新 `search` / `job` 返回的完整职位链接，或该会话缓存中的职位 ID。保留完整链接里的站点上下文，不自行构造 `securityId`、`lid`。目标模糊时先查询并准备候选职位，缺少可唯一确定的公司和职位时再让用户选择。

## 预览和选择附件

```powershell
node bin/boss.js apply preview '<实际职位完整链接或 ID>' --json
```

`apply '<职位>'` 等同预览。检查返回的 `job`、`resumes`、`selectedResume`、`canSendResume` 和 `executed`：

- `resumes` 里的 `id` 才是 `--resume-id`；不要使用文件名、列表序号或本地路径代替。
- 只有一份附件时 CLI 可自动选中。多份附件须显式传 `--resume-id`；可根据用户已指定的唯一附件名称/ID 精确匹配，无需重复询问。用户未选定或名称不唯一时，展示附件名称及对应 ID 后询问，不能自行选择第一份或最新一份。
- 没有附件时告知用户在网站正常上传。CLI 没有上传命令，不虚构上传功能。
- `canSendResume:false` 表示站点不允许当前投递。`null` 或 `true` 均不保证提交成功，实际仍有站点预检。
- 投递预览不代表附件已经发送，也不证明用户具备任何资格或职位仍可投递。

选定附件后使用同一目标再预览，把职位、公司、附件名称及任何跟进文字整理为可核对结果：

```powershell
node bin/boss.js apply preview '<实际职位完整链接或 ID>' --resume-id '<实际附件 ID>' --json
```

## 在授权范围内提交

调用技能本身不授权真实投递。用户只要求预览或比较时到此完成。用户已经明确要求投递，且职位和附件已确定，则在核对预览后直接执行，不重复索取确认。没有投递授权时，先完成上述可核对结果，再询问是否提交。不要自动加入未请求的附件、职位或跟进消息。

```powershell
node bin/boss.js apply send '<实际职位完整链接或 ID>' --resume-id '<实际附件 ID>' --execute --json
```

不加 `--execute` 的 `apply send` 仍是预览；`apply preview --execute` 是非法用法。按当前 shell 正确引用 URL、ID 和正文，防止参数被当作 shell 代码。

用户授权附带跟进文字时，先带相同文字预览，再提交：

```powershell
node bin/boss.js apply preview '<实际职位完整链接或 ID>' --resume-id '<实际附件 ID>' --message '已授权的跟进正文' --json
node bin/boss.js apply send '<实际职位完整链接或 ID>' --resume-id '<实际附件 ID>' --message '已授权的跟进正文' --execute --json
```

`--message` 是附件提交成功后另发的文字消息，正文为去除首尾空白后的 1–999 个字符；并非简历备注或附件内容。只有用户已授权跟进消息才加此选项，单纯“投递简历”不等于发送额外文字。

## 解释结果和恢复

- `executed:false` 只表示预览。`executed:true` 并有服务端成功回执时，才报告附件已提交；不要将打开页面、点击按钮或本地消息对象当作成功。
- `PARTIAL_SUCCESS` 且 `details.resumeSent:true`：附件已投递、后续文字未确认。明确说明这两部分，禁止为了补发文字而重跑投递。需要跟进时先读取聊天记录，确定没有重复风险后仅处理消息。
- `DELIVERY_UNCONFIRMED`：提交可能已经发生，先核对网站投递记录和相关会话，不自动重试；记录仍不明确时报告“提交状态未知”，让用户核对后决定。
- `SITE_ACTION_UNAVAILABLE`：查看浏览器中职位网申、投递按钮或站点预检提示。需要额外确认、网站上传或其他渠道时如实说明并停止，不强行绕过。
- 附件 ID 无效或列表变化时重新预览；多份附件仍需明确选择。站点缺少上下文、职位失效或结构变化时保留错误，不伪造参数。
- 登录、验证、限流或网络错误按实际提示处理；手动验证码由用户完成。重新登录不代表可以重试状态未知的投递。

使用 JSON 错误中的 `code` / `details` 判断后续操作，不能只依据退出码决定重试。每个职位的成功、未提交、部分成功、状态未知分别记录，避免重复投递。隔离浏览器测试不等于真实账号已投递成功。
